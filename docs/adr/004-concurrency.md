# ADR-004 行级锁 + 数据库排除约束

Status: PROPOSED

选择设备行级锁、事务和 GiST 排除约束；未选仅应用层先查再插入，也暂不引入 Redis 分布式锁。理由：避免竞态，数据库兜底。代价：同设备写操作串行化，需真实并发测试。

评审状态：待团队评审；批准信息尚未填写。关联业务补充见 [规则审查](../rule-review.md)；实际验证见 [验证记录](../verification.md)。

2026-11-10技术验证：真实PostgreSQL17.11中，设备锁服务通过20独立连接×20轮和混合预约/维护竞争；迁移及排斥约束测试通过。绕过服务的原始插入出现过40P01死锁中止，支持保留统一锁入口的必要性。技术证据不构成团队批准，状态仍PROPOSED。
