## 1. 项目背景

高校实验室通常配备多种供成员共享使用的科研和实验设备，包括 GPU 工作站、计算服务器、电子仪器、测量设备等。

在一些缺少统一预约工具的实验室中，设备使用时间可能通过微信群、口头沟通或人工表格协调。这种方式在设备数量有限、多人需要使用同一设备的情况下，可能出现：

1. 设备状态不透明：成员无法及时了解设备是否空闲。
2. 预约信息分散：使用计划分散在聊天记录中，难以统一查看。
3. 预约冲突：多个成员可能同时申请相同设备的重叠时段。
4. 管理成本较高：管理员需要人工维护设备状态和协调冲突。
5. 使用记录难追溯：预约、取消和设备停用等操作缺少统一记录。

本项目拟通过轻量级 Web 应用集中管理实验室共享设备和预约信息。

以上是待验证的目标场景，不代表已完成真实用户调研。

## 2. 问题陈述

### 2.1 核心问题
当多个实验室成员希望使用同一台共享设备时，现有分散式人工预约方式难以及时、可靠地协调设备使用时间。

### 2.2 核心价值主张
让实验室成员能够自主查询、预约和管理共享设备使用时段，同时从系统层面防止同一设备出现有效预约时间冲突。

## 3. 目标用户

### 3.1 普通成员（Member）
- 高校实验室研究生、科研助理或其他授权成员。
- 需要使用共享设备。
- 需要查询设备、创建预约、查看个人预约、取消未开始预约。

### 3.2 设备管理员（Administrator）
- 负责维护共享设备信息和可用状态。
- 需要添加/编辑/停用设备。
- 需要设置维护时段。
- 需要查询全部预约并处理异常情况。

### 3.3 权限边界（候选）
| 操作 | 普通成员 | 管理员 |
|---|---|---|
| 查看设备 | 允许 | 允许 |
| 查询可预约时段 | 允许 | 允许 |
| 创建预约 | 允许 | 允许 |
| 查看个人预约 | 允许 | 允许 |
| 取消本人预约 | 允许 | 允许 |
| 管理设备 | 禁止 | 允许 |
| 设置维护时段 | 禁止 | 允许 |
| 查看全体预约 | 禁止 | 允许 |

## 4. 产品目标

- G-01：集中管理设备信息。
- G-02：实现成员自主预约。
- G-03：保证预约一致性，避免同一设备存在重叠的有效预约。
- G-04：降低管理员协调成本。
- G-05：使需求、架构、故事和测试可追溯。

## 6. 产品范围

### 6.1 MVP 范围
- 用户登录与角色权限。
- 设备列表和详情。
- 设备新增、编辑、启用、停用。
- 预约日程查询。
- 创建预约与冲突检查。
- 查看个人预约、取消预约。
- 管理员查询预约。
- 维护时段管理。
- 必要的业务操作日志。

### 6.2 范围外
- 设备采购、支付与结算。
- 设备远程控制。
- GPU 调度器集成。
- 微信小程序或原生 App。
- 多实验室多租户。
- 学校统一身份认证实际对接。
- 短信、邮件、微信通知。
- AI 智能排程。
- 复杂多级审批。

## 7. 核心业务规则（候选）

- BR-01：创建预约必须完成身份认证。
- BR-02：一次预约关联一个用户、一台设备和一个连续时间区间。
- BR-03：时间区间使用半开区间 `[start_time, end_time)`。
- BR-04：开始时间早于结束时间。
- BR-05：同一设备的有效预约不得重叠。
- BR-06：预约状态初步定义为 ACTIVE、CANCELLED；已结束可按时间计算显示。
- BR-07：普通成员只能取消本人尚未开始的有效预约。
- BR-08：设备状态为 AVAILABLE 或 DISABLED。
- BR-09：设备停用不自动删除或取消已有预约。
- BR-10：维护时段不得与有效预约重叠。
- BR-11：管理员异常取消必须记录原因和操作者。
- BR-12：时间存储与展示时区策略待团队确认。

## 8. 核心使用场景

### S-01 成员预约设备
登录 → 选择设备 → 查看日程 → 选择时间 → 提交 → 服务端验证 → 原子创建预约 → 返回结果。

### S-02 两个成员同时预约
两个成员同时争抢同一设备同一时段，系统必须保证一个成功、另一个得到业务冲突结果。

### S-03 成员取消预约
成员选择本人尚未开始的有效预约，取消后保留历史记录并释放时段。

### S-04 管理员设置维护
管理员选择设备和维护时段；系统检查已有预约冲突，无冲突才保存维护占用。

## 11. 主要风险

- 并发预约造成重复占用。
- 项目范围膨胀。
- 模块设计不一致。
- 需求歧义。
- 缺少过程证据。
- 技术栈超出团队能力。
- 维护与预约产生冲突。

## 12. 待确认假设

- 实际实验室人数与设备数量。
- 是否需要管理员审批。
- 最短/最长预约时长。
- 最远提前预约期限。
- 设备停用后的已有预约处理。
- 维护时段是否允许取消。
- 管理员能否取消已开始预约。
- 是否允许成员同时预约多台设备。
- 用户账户是预置还是自助注册。
- 目标时区。

## 13. MVP 完成定义

- 应用可启动。
- 用户可以查询设备并完成预约。
- 冲突预约被拒绝。
- 并发测试不产生重复占用。
- 成员可以查看和取消个人预约。
- 管理员可以管理设备与维护时段。
- 权限测试通过。
- 代码、测试、文档和运行说明纳入 Git 仓库。

**结论：** LabReserve 定位为高校小型实验室轻量级设备预约系统，以可验证的预约一致性作为最核心的产品和工程目标。
