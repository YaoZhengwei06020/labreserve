# LabReserve — Project Context

**版本：** v0.1\
**状态：** 待团队确认

本文件为 AI 开发智能体提供项目级约束。团队批准架构后生效。

## 技术与架构规则

**RULE-01：** 后端统一使用 Django 5.2 LTS；未经 ADR 审查不得引入 FastAPI、Flask 等第二套后端框架。

**RULE-02：** 前端采用 Django Templates、Bootstrap 5 和必要的原生 JavaScript；不得自行引入 React、Vue 或独立 SPA 框架。

**RULE-03：** 主数据库统一使用 PostgreSQL。不得用 SQLite 并发测试结果作为 NFR-01 通过证据。

**RULE-04：** 所有创建或变更设备占用的操作必须经过 booking 业务服务层；View 不得自行实现第二套预约逻辑。

## 数据一致性规则

**RULE-05：** 有效预约和维护统一通过 EquipmentSlot 管理，不得创建绕过冲突约束的占用表。

**RULE-06：** 创建预约、维护时段和修改设备可用状态时，必须使用统一数据库事务和设备锁策略。

**RULE-07：** 不得仅依赖应用层冲突查询保证并发正确性；数据库排除约束必须保留并测试。

**RULE-08：** 预约时间采用带时区表示，界面时区候选为 Asia/Shanghai；时间区间采用 `[start,end)`。时区待团队确认。

## 安全规则

**RULE-09：** 所有设备管理、预约取消和维护管理操作都必须执行服务端授权；隐藏前端按钮不构成权限保护。

**RULE-10：** 禁止在源代码、测试代码或 Git 提交中包含真实密码、API 密钥及个人敏感信息。

## 测试与交付规则

**RULE-11：** 修改预约冲突、时间规则、设备状态或权限逻辑时，必须更新对应自动化测试；未实际执行不得声称测试通过。

**RULE-12：** Story 完成前必须检查对应 FR/NFR 验收标准；未满足验收条件不得标记 Done。

架构变化时必须同步更新规则。当前所有规则均待团队确认。
