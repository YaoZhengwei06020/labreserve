# 业务规则一致性审查

状态：PROPOSED，待团队评审。基线保持4 Epic、13 Story、15 FR、6 NFR、7 ADR及12条项目规则。

## 生命周期与并发规则

| 问题 | 候选规则 | 追踪 |
| --- | --- | --- |
| 管理员取消预约 | 仅开始前允许，非空原因必填，包括取消自己的预约；运行中异常中止不在本版本范围 | BR-07/11、FR-15、US-13、ADR-005 |
| 设备停用 | 拒绝新增预约和维护，保留既有历史和未来占用；管理界面提示未来占用；可按规则取消，重新启用不恢复已取消记录 | BR-09、FR-06、US-06、ADR-004/006 |
| 维护取消 | 仅ADMIN在开始前有原因取消，同事务保存审计；只释放该维护，不恢复历史预约；不提供原地修改时段 | BR-10/11、FR-14、US-10、ADR-003/004/005 |
| 维护冲突 | 整体拒绝，不自动取消预约；取消预约和另建维护为独立业务操作 | FR-14、US-10 |
| 锁顺序 | atomic内先锁Equipment，再按需锁EquipmentSlot；启停操作使用同一设备锁；GiST排斥约束兜底 | BR-11、RULE-04～07、ADR-004 |
| 幂等与审计 | 先校验权限；重复取消保留第一次审计，不新增成功日志；日志失败整体回滚 | BR-07/10/11、US-12/13 |
| 管理员角色 | ADMIN业务组独立于Django is_staff标记，由服务端检查 | FR-02、US-02、ADR-005 |

上述规则已同步到PRD、Story验收条件与技术验证服务。维护取消归入FR-14/US-10，不增加需求或Story数量。

## 待评审参数

最短30分钟、最长4小时、提前7天为建议值，尚未定稿；spike只验证带时区、未来及正时长，不视为FR-10/US-08完整验收。时区、账户开通方式、是否允许同一成员跨设备并发预约、无需审批假设及Sprint估点仍待团队确认。

审查记录与技术测试不替代正式决策，批准状态以ADR及决策日志为准。
