# LabReserve — 产品需求文档（PRD）

**版本：** v0.2 候选修订（保留原始编号）\
**状态：** 待团队评审\
**上游文档：** product-brief.md

## 1. 产品概述

为高校实验室提供简单、可靠、可维护的共享设备预约平台。用户包括 MEMBER 和 ADMIN 两种角色。目标规模是假设：20–50名成员、10–30台设备、单个实验室、Web 应用。

## 2. 产品范围

### In Scope
登录与权限、设备列表/详情、设备增改停启、预约日程、创建预约、冲突检测、个人预约、取消、管理员查询、维护时段、业务操作日志。

### Out of Scope
远程设备控制、GPU调度、支付、微信小程序、跨实验室多租户、统一身份认证对接、消息通知、AI排程、复杂审批。

## 3. 业务规则

- BR-01：创建、取消和管理预约前必须完成身份认证。
- BR-02：一次预约关联一个用户、一台设备和一个时间区间。
- BR-03：使用半开区间 `[start, end)`。
- BR-04：开始时间早于结束时间；建议最短30分钟、最长4小时、提前7天预约（均待团队确认）。
- BR-05：同一设备的有效预约时段不得重叠。
- BR-06：预约持久化状态为 ACTIVE、CANCELLED；结束状态可按时间计算展示。
- BR-07：普通成员只能取消本人尚未开始的有效预约；管理员也仅可取消未开始预约，必须非空原因。重复取消先授权再幂等返回，不改首次审计。开始后取消或紧急中止不在本候选版本内。
- BR-08：设备状态 AVAILABLE / DISABLED。
- BR-09：停用设备不自动删除或取消既有预约/维护；拒绝新增预约和维护，既有未来占用仍可按规则取消。重新启用不恢复已取消记录。管理页须提示仍保留的未来占用。
- BR-10：维护与预约共享 ACTIVE 占用排斥约束；维护冲突整体拒绝、不自动取消预约。管理员可在开始前填写原因取消维护，只释放该维护，不恢复历史预约；重复取消保留首次审计。新建维护同样要求设备启用、未来、正时长。
- BR-11：管理员取消预约或维护，必须在同一事务中记录操作者、时间、目标、非空原因；失败整体回滚。创建/取消占用和启停设备统一先锁 Equipment，再锁 EquipmentSlot（需要时），不可反序。
- BR-12：建议按 Asia/Shanghai 展示时间，待团队确认。

重叠判定：
`A.start < B.end AND B.start < A.end`

## 4. 功能需求（15条 FR）

### FR-01 用户登录
有效账户可登录。
- AC：正确凭据登录成功。
- AC：错误凭据不产生有效会话。
- AC：未登录用户不得访问受保护资源。

### FR-02 基于角色的访问控制
- AC：MEMBER 可使用允许的预约功能。
- AC：MEMBER 调用管理接口返回403。
- AC：ADMIN 可执行授权管理功能。
- AC：修改前端参数不能绕过服务端授权。

### FR-03 当前用户信息
- AC：登录用户可查看自己的用户标识和角色。
- AC：未登录不可获取受保护信息。

### FR-04 设备列表与详情
设备字段至少包括编号、名称、描述、位置、状态。
- AC：列表展示设备。
- AC：按编号查询详情。
- AC：不存在设备返回明确404。

### FR-05 新增和编辑设备
- AC：管理员创建有效设备后可查询。
- AC：设备编号唯一。
- AC：修改后查询反映修改。
- AC：普通成员不能新增或修改。

### FR-06 启用与停用设备
- AC：DISABLED 设备不能接受新预约。
- AC：重新启用后可以在满足条件时接受预约。
- AC：停用保留历史和未来预约/维护，新建预约/维护被拒；管理页提示保留的未来占用。取消和重新启用按 BR-09。

### FR-07 预约日程查询
- AC：返回指定设备有效预约。
- AC：CANCELLED 不再占用时段。
- AC：维护时段体现为不可预约。
- AC：不泄露其他成员不必要的隐私。

### FR-08 创建预约
前置条件：已登录、设备可用、时间合法、时段无冲突。
- AC：合法请求创建 ACTIVE 预约。
- AC：缺少参数返回参数错误。
- AC：设备不存在返回相应错误。
- AC：成功后可在个人预约中查询。

### FR-09 预约冲突检测与并发一致性
- AC：09:00–10:00存在时，09:30–10:30被拒绝。
- AC：09:00–10:00存在时，10:00–11:00允许。
- AC：20个并发请求竞争同一设备同一时段，恰好1个成功，19个业务冲突。
- AC：数据库最终无重叠有效预约。
- AC：冲突不留下无效记录。

### FR-10 预约参数验证
- AC：结束时间早于或等于开始时间时拒绝。
- AC：开始时间位于过去时拒绝。
- AC：超出团队批准后的时长限制时拒绝；30分钟/4小时/7天仍是待批参数，当前 spike 仅验证未来、正时长和带时区，不声称通过此项验收。
- AC：设备停用时拒绝。
- AC：与维护时段重叠时拒绝。

### FR-11 查看个人预约
- AC：只返回当前用户有权查看的预约。
- AC：包含设备、时间和状态。
- AC：区分有效、取消、已结束。

### FR-12 取消个人预约
- AC：本人取消未开始 ACTIVE 预约后状态变为 CANCELLED。
- AC：取消后释放时段。
- AC：不能取消其他用户预约。
- AC：重复取消不产生重复状态变化。
- AC：普通成员不能取消已开始预约。

### FR-13 管理员查询全部预约
- AC：管理员可查询所有预约。
- AC：支持设备、用户、状态筛选。
- AC：普通成员不能访问管理员接口。

### FR-14 维护时段管理
- AC：创建有效维护时段后该时段不可预约。
- AC：与已有 ACTIVE 预约重叠时拒绝直接创建。
- AC：普通成员不能创建或修改维护时段。
- AC：与已取消预约重叠不构成冲突。
- AC：ADMIN 可在维护开始前填写非空原因取消，保存审计；重复取消幂等，开始后拒绝。
- AC：取消维护只释放维护，不恢复任何已取消预约；普通成员不能取消维护。
- AC：本版本不提供原地修改时段；需按规则取消旧维护后另建，两个动作各有明确结果。

### FR-15 管理员异常预约处理
- AC：管理员仅能取消尚未开始的有效预约，必须提供非空原因（含自己的预约）；开始后拒绝。
- AC：操作后状态正确更新。
- AC：保存操作者、时间、目标预约和原因。
- AC：普通成员不能执行。

## 5. 非功能需求（6条 NFR）

### NFR-01 数据一致性（P0）
20个独立并发请求竞争同一设备同一空闲时段，恰好1个成功、19个业务冲突；连续20轮；数据库最终只有一条对应有效预约且无重叠。真实 PostgreSQL、独立连接、数据库最终状态检查。

### NFR-02 安全与权限（P0）
预设未登录、普通成员越权、跨用户取消测试全部正确拦截；密码不得明文存储。

### NFR-03 核心查询性能（P1）
测试数据：50用户、30设备、1000预约。设备列表 P95≤500ms，单设备日程 P95≤800ms；不得出现未处理服务端错误。需记录测试环境。

### NFR-04 可部署性（P0）
README 写明前置条件、数据库初始化、启动、测试命令；全新评审环境按文档可部署。

### NFR-05 可靠性（P1）
非法参数不产生脏数据；冲突不导致崩溃；预约创建失败不留下部分记录；重启后有效预约仍可查询。

### NFR-06 基本可用性（P2）
至少3名测试者；在统一简短说明后，60秒内完成简单预约；记录实际时间和失败情况。

## 6. 核心业务流程

创建预约：登录→选设备→查日程→填时间→提交→服务端校验→并发安全地创建→返回结果。

取消预约：选择个人预约→检查归属和状态→改为 CANCELLED→保留历史→释放时段。

设置维护：管理员选设备和时段→检查冲突→无冲突才保存。

## 7. 逻辑数据模型

- User：id、username、password_hash、display_name、role、created_at。
- Equipment：id、code、name、description、location、status、created_at。
- Reservation：id、user_id、equipment_id、start_time、end_time、status、created_at、cancelled_at。
- Maintenance：id、equipment_id、start_time、end_time、reason、created_by。
- OperationLog：id、actor_id、action、target_type、target_id、reason、created_at。

后续架构候选将预约和维护统一映射到 EquipmentSlot，以解决跨表冲突约束问题；需团队批准。
